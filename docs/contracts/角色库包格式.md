# 角色包格式（.zip）

角色包的**唯一事实源**——包结构、manifest 字段、完整性门槛，以及三侧各自的规则：客户端导入/导出、市场服务端上传解析、make-character 打包。三侧共用同一份格式，不再各留一份描述。

> **格式标识符 ≠ 文件后缀。** 包内 `manifest.format` 恒为 `"tomochar"`（服务端也校验它，改值等于改协议）；而**导出的文件后缀是 `.zip`**（2.0 起；此前是自定义的 `.tomochar`）。两者互不相干，详见 §包结构 → 文件扩展名。

实现：客户端 `electron/src/service/CharacterArchiveService.ts`；服务端 `CharacterPackageReader` / `SpritesheetCutter`（市场服务端仓库 `tomo-server`，见 [CLAUDE.md](../../CLAUDE.md)「跨项目文档索引」）。

依赖：[PetDex宠物包格式](PetDex宠物包格式.md)（身体段的格式标准）、[事件目录契约](事件目录契约.md)（事件名一律用抽象事件）。

> **包与 Agent 无关**：`event` 是抽象事件名，任何 Agent 都能导入任何包，零映射（§跨 Agent 使用）。

## 包结构

**v2 = 合法 PetDex 包 + tomo 扩展段**（超集；其他 PetDex 消费端忽略扩展段后仍能正常渲染）：

```text
<name>.zip                     # ZIP（未压缩，level: 0）
├── pet.json                   # 身体段：PetDex 必需
├── spritesheet.webp           # 身体段：PetDex 必需（PetDex 亦接受 spritesheet.png）
├── manifest.json              # tomo 扩展段：格式描述
└── audio/<uuid>.<ext>         # tomo 扩展段：音频条目
```

- **身体段的两个文件在根级**，条目名即 `pet.json` / `spritesheet.webp`（身体段对齐 [PetDex宠物包格式](PetDex宠物包格式.md) §1）
- `audio/` 是约定目录，条目为**裸文件名**（拒绝路径/穿越）；条目名 = uuid，全 ASCII，编码问题从源头消除

**大小上限**：单个包 ≤ 200MB（服务端上传侧拒绝超限包）。

### 文件扩展名

**导出写 `.zip`，导入两个后缀都认。**

- 2.0 起，应用导出与 `pack.js` 产物的后缀都是 `.zip`；1.0 存量包的 `.tomochar` **继续可导入**——两者字节同构，都是 `level: 0` 的标准 ZIP
- **导入侧从不检查后缀**：分派只看包内有没有 `manifest.json`（[CharacterArchiveService.ts](../../electron/src/service/CharacterArchiveService.ts) 的 `importCharacterFromBuffer`）。文件对话框的过滤器同时列出两个后缀是**给人看的**，不是给代码判的——别把它当残留清理掉
- 后缀不参与判定，所以损坏文件、被改名的非 zip，都在解压那一步失败并报「不是有效的 zip 文件」
- ⚠️ **不要把 `.zip` 解压后重新压缩**：资源管理器会把它当普通压缩包，解压再压缩极易多套一层目录（条目变成 `<name>/manifest.json`），导入会以「既没有 manifest.json，也没有 pet.json」拒绝——那个报错看不出真正的原因是层级。要改包内容，请用 tomo 重新导出。

## 没有头像

包内**没有 `avatar.png`**，角色目录里也没有。2.0 起「角色长什么样」唯一由**身体段**表达：宠物窗口、角色卡片、市场预览一律从 spritesheet 派生（宠物窗口与管理界面直接渲染帧；市场列表由服务端裁出第一行，见《角色库公开接口契约》）。

- **包内出现 `avatar.png` 时导入侧与服务端一律忽略**：旧 v2 包（2.0 发布前的开发期格式）与手工打包会带它，忽略即可，不报错、不落盘
- **本地存量角色的 `avatar.png` 文件不删**（用户资产）；只是代码链路不再读写它

## manifest.json

`version: 2`：

- `format: "tomochar"`（**格式标识符，不是文件后缀**——导出文件叫 `.zip`，这个值不变；服务端同样校验它）、`version: 2`
- `name`、`exportedAt`
- `events: { event, audios: [{ file, name }] }[]` — **该角色有音频绑定的事件**（「角色事件集」概念已随抽象事件层消失：能播什么 = 有哪些绑定，因此导出时每条 `event` 至少带一条 audio）
  - `event`：**可绑语音的抽象事件名**（**8 个之一**，见 [事件目录契约](事件目录契约.md) §四的 `VOICE_EVENTS`）：
    `session-start` / `session-end` / `prompt-submit` / `turn-complete` / `turn-failure` /
    `permission-request` / `post-tool-use-failure` / `task-completed`。
    目录里另外 8 个抽象事件（`post-tool-use` / `file-edited` / `task-created` / `subagent-start` /
    `subagent-stop` / `pre-compact` / `post-compact` / `session-error`）**仍驱动桌宠状态，但不可绑语音**，
    因此不会出现在任何合法包内 —— 出现即拒绝
  - 导入侧容忍 `audios: []`（空数组合法，只是不建绑定）；导出侧不会产出这种条目，服务端上传也把它当作「该事件缺语音」拒绝
  - `file`：包内条目名（uuid 裸文件名，`audio/` 约定目录）
  - `name`：UI 展示名（导出时取 DB 展示名列；缺 `name` 字段的包导入时明确拒绝）

**没有 `mainAgent`**（v1 有）。抽象事件名天然跨 Agent 通用，包不再需要标注来源 Agent，服务端也不需要——同一个包对各家 Agent 一视同仁。

**没有 `body` 字段**：身体的有无由包内是否存在 `pet.json` + `spritesheet.(webp|png)` 直接表达，不在 manifest 里冗余登记（避免两处漂移）。

## 完整性与导入/导出的不对称

| 方向 | 要求 |
|------|------|
| **导入** | 允许**只有身体**（纯 PetDex 包，无 manifest.json）或**只有语音**（无 pet.json/spritesheet）；两者都缺 → 拒绝 |
| **导出 / 市场** | **必须三件**：`pet.json` + `spritesheet.(webp\|png)`（身体）+ **8 个可绑事件各至少一条音频绑定**（语音）。缺任一 → 拒绝导出/拒绝上架，错误明确上报并**逐个点名缺哪个事件** |

理由：导入是用户拿到什么就先用什么（PetDex 画廊导入只给身体）；导出是**产出要分享给他人的对象**，半成品会污染市场、也会让下一个用户拿到一个"什么都干不了"的包。

语音那一件的口径是**"8 个事件各 ≥1 条"，不是"总共 ≥1 条"**：分享出去的包要在任何 Agent 上都"能开口"，缺哪个事件，下载方就在那个场景哑掉——而那往往正是"陪伴感"最容易被感知为失效的时刻（失败时没声音、等待授权时没声音）。自己装着玩的角色不受此约束，导入侧照旧容忍残缺。

判定入口是 `missingVoiceEvents()`（[src/shared/events.ts](../../src/shared/events.ts)）——客户端导出、详情页前置检查、make-character 的 `pack.js` 三处共用，别在别处再写一遍差集。

**身体是导出的硬门槛**，因为它是包内唯一的可视资产——没有身体，下载方在桌面上什么都看不到（tomo 不提供任何兜底形象），市场上则是一屏无法区分的条目。想分享就必须真的给角色配一只宠物（来自 PetDex 或自备）。**没有宠物就不是桌宠**：无身体角色不上桌面、不进包，不存在"借一只"的降级路径。

## 跨 Agent 使用

包里的 `event` 已经是抽象事件名，**任何 Agent 都能导入任何包，零映射**。目标 Agent 够不到某些抽象事件时（如 Codex 没有 `turn-failure`），对应的绑定**保留在库里 + UI 标灰**（不丢数据、可往返；换回可达的 Agent 即刻恢复）。新接入的 Agent 对所有存量包自动可用，无需重新导出。服务端不预生成跨 Agent 段，不改造包。

## 纯 PetDex 包（无 manifest.json）

没有 `manifest.json`，但客户端**导入侧接受**：包里只有 `pet.json` + `spritesheet.(webp|png)`。导入后是一只**静默宠物**：有身体、零音频绑定，用户可自行配音或「更换身体」给别人。

**只收 zip**：PetDex 的官方形态是目录（`npx petdex install <slug>` 落到 `~/.petdex/pets/<slug>/`），tomo 请先把它压成 zip 再导入——不提供「从文件夹导入」（取出的字节完全相同，多一条路径只是多一处要跟着改的地方）。

- **角色名**：`manifest.name`（tomo 包）或 pet.json 的 `name` → `displayName` → `slug` 依次取第一个非空字符串；都没有 → 拒绝（「pet.json 里没有可用的名字」）。PetDex 未定义 pet.json schema，野外字段名不统一，故按序兜住。重名自动追加 `" (2)"`，包文件名不参与命名
- **校验强度**：只查「`pet.json` 存在且是合法 JSON」「`spritesheet.(webp|png)` 存在且扩展名在白名单内」。**不校验图集几何**——那由宠物窗口渲染器在加载时判定，失败走可见的错误上报（宠物留空 + 界面提示）
- 这种包**上传市场不适用**——服务端只收带 `manifest.json` 的 v2 包（后缀白名单本身 `.zip` / `.tomochar` 都收）

## v1 旧包：上传与导入都拒绝

v1 包（`version: 1`、单段结构、`mainAgent`、原生事件名、无身体段）**不再被接受**——判别依据是 `version`，与文件后缀无关：

- 客户端导入：明确拒绝并提示「旧版角色包已不再支持，请使用 2.0 版本导出/下载的角色包」
- 服务端上传：`version !== 2` → 拒绝

理由：v1 的事件名是各家 Agent 的原生名，接受它就意味着要在导入侧永久保留一条"原生名 → 抽象名"的翻译路径和它的测试面；而存量 v1 包只有 20 个且全部由 [characters/](../../characters/) 产出、可重新打包上传，为此留一条永久的兼容通道不划算。**这是一次性切换**——发布顺序因此被卡死：市场旧条目在 2.0 发布前下架，20 个角色改用带身体的原型宠物包重新上架（见 [第二阶段实施计划](../tomo第二阶段实施计划.md) 风险表）。

## 客户端侧

### 身体段落盘约定（不进 DB）

角色目录根级 `pet.json` + `spritesheet.(webp|png)`，**存在即事实**，本阶段零 schema 迁移。覆盖身体时清掉另一种扩展名。

`CharacterBodyService.sheetUrl(characterId)` 解析「该角色该显示哪张图」（有身体 → `tomo-res://` 带内容指纹；没有 → `null`），宠物窗口与管理界面 `PetPreview` 共用。

**没有身体 = 没有宠物**：宠物窗口隐藏，不存在任何兜底形象（内置默认宠物机制已删除；`assets/pets/default/` 降级为不被代码引用的离线资产）。

文件访问走 **`tomo-res://`**（通用本地资源协议，host 即资源根）：

- `char/<id>/<rel>` 是角色目录
- `petdex/<来源>/<slug>/<rel>` 是**本机已安装的 PetDex 宠物**（「添加宠物」弹窗的缩略图，那些文件不属于任何角色目录）

**加资源根，不加协议**——两条支路共用同一句安全模型：「resolve 后必须落在那根之内」；`petdex` 那支**只允许相对路径**（那些目录是用户的下载目录，不该成为读任意文件的跳板）。

### 图集 URL 必须内容寻址

`sheetUrl()` 拼出的 URL 带 `?v=<mtimeMs>-<size>` 指纹。理由——URL 原本只由 (角色 id, 文件名) 决定，而「更换身体」是**同址换内容**（PetDex 钉死文件名 `spritesheet.webp`），主进程来源去重、渲染进程 `loadPetSheet` 解码缓存、浏览器缓存会集体命中旧图，表现为「换完宠物不换脸」。协议处理器只看 pathname，query 天然被忽略，因此带指纹零成本。**今后任何以角色资源 URL 为键的缓存，都要先确认该 URL 随内容变化。**

### 展示：一律从 spritesheet 派生

宠物窗口与角色卡片直接渲染帧，不落任何静态图；市场列表由服务端裁出 `coverUrl`（图集**第一行**＝idle 行，客户端按 idle 节拍逐格轮播）。

市场两处的用法（决策 39）：**列表用 `coverUrl`**——只有 idle 一行、约整图 1/9 的字节，所以封面上的宠物只会呼吸眨眼；**详情用整图 `spritesheetUrl`**，喂给与本地「角色详情页」宠物栏**同一个** `PetStatePlayer`（大预览 + 九态格子），九个动作逐个可点。

**导入侧不校验图集几何**，几何的唯一裁判是渲染器，加载失败**留空 + 明确上报**（不静默兜底、不退回上一只）。

### 几何校验只有渲染进程做得了

主进程（Node）**不解码图片**——Node 没有图像解码能力，Electron 的 `nativeImage` 只接 PNG/JPEG、**不接 WebP**（而 PetDex 生态与 hatch-pet 产的正是 `.webp`）。所以导出的身体门槛落在**详情页前置检查**（复用 `loadPetSheet` 的解码结果，不合规抛 `sheetGeometryError`），`CharacterArchiveService` 只判身体文件在不在。

**别再想着给主进程一个几何校验**——那要引入图像依赖，且会与渲染器立成两把尺子。服务端是唯一的例外，它本来就在解码图集（要裁 `coverUrl`），顺手校验零成本（见§服务端上传解析规则）。

### 导入规则

- **后缀不参与判定**：`.zip` 与 1.0 存量 `.tomochar` 都读，按包内内容分派（有 `manifest.json` → tomo 包，没有 → 纯 PetDex 包）。这条有回归测试守着（`CharacterArchiveService.test.ts` 的「导入不看扩展名」），别在导入路径上新增后缀检查
- 音频**不裁剪**：包内引用的 `audio/` 条目全量落盘，`events[].audios` **逐条建绑定**（零映射，不做任何取舍）；本地角色永远单 Agent，角色目录 = 包本体
- 非 UTF-8 条目名（GBK 等外部工具产物）**明确拒绝**，不探测
- 音频格式限定 `mp3/wav/ogg/m4a/flac/aac/opus/webm`（包内引用条目全量校验）
- 先全量校验再落库落盘（失败无半状态）；事件名严格校验（必须 ∈ 语音 8 词白名单 `VOICE_EVENTS`——**不是**「∈ 抽象事件目录」那 16 个，另外 8 个只驱动桌宠状态、不可绑语音）

> **「只收 zip」是导入侧的规矩**（导入要建一个新角色，得多问一次"这个目录叫什么名字"）。**换身体不需要**：`npx petdex install` 装的宠物在「添加宠物」弹窗里直接列出来，点一下就用（`PetdexLibraryService` 扫 `~/.petdex/pets` 与 `${CODEX_HOME:-~/.codex}/pets`）。两条路的身体段校验是同一套 `prepareBody`。

### 音频绑定模型（event_audio，定位与展示解耦）

- `path`：文件定位符——内嵌 = `audio/<uuid>.<ext>`（相对路径）；手动添加 = 外链**绝对路径**（不复制文件）
- `name`：UI 展示名（默认 = 文件名去音频扩展名；绑定页点击名称行内编辑，空名/超 100 字符拒绝；missing 绑定也可改）
- 外链源文件缺失：绑定列表**标红** + 播放明确报错（禁止静默降级）
- 导出：内嵌复用磁盘 uuid 名、外链读绝对路径临时生成 uuid；任一音频缺失 → **整体拒绝导出**
- `tomo-res://` 协议：外链绝对路径按 DB 引用**白名单校验**后放行（防借协议读任意本地文件）
- 删除绑定：只删 DB 行，**文件一概不动**（内嵌/外链统一——解绑是纯元数据操作，无毁灭性；同一文件可被多条绑定引用）；孤儿文件随角色删除整目录清理，**绝不删外链源文件**

## 服务端侧：上传解析规则

- 用 ZIP 解析读取包内 `manifest.json`；读不到或 JSON 解析失败 → 拒绝（返回「不是有效的角色包」）。
- 校验：`format === "tomochar"`；**`version === 2`**（v1 一律拒绝，见上）；`name` 非空且 ≤ 100 字；`events` 数组存在且 `events[].event` 全部 ∈ **可绑语音的 8 个抽象事件**（见 manifest 一节）。
- 校验完整包三件：`pet.json` + `spritesheet.(webp|png)` + **8 个可绑事件各至少一条音频**，缺任一 → 拒绝并返回具体缺哪件；音频那件要**逐事件点名**（`还缺：turn-failure / task-completed`），不能只说一句「音频不全」。
- **生成预览图：从 `spritesheet` 裁下第一行（PetDex 的 idle 行）整行**，矩形 = `(0, 0, 图宽, 帧高)`，**不缩放**，上传 OSS 作为 `coverUrl`。同时把 `spritesheet` 原图上传 OSS 作为 `spritesheetUrl`（详情页动画预览用）。
  - **为什么是行不是列**：PetDex 网格 8 列 × N 行里**行 = 状态、列 = 该状态内的帧序号**（第 0 行 idle、第 1 行 running-right …）。裁第一列得到的是「9 个状态各自的第 0 帧」——各状态首帧多半是同一个中性/蓄力姿势，连起来是翻页而不是动画；第一行才是真正的 idle 循环（呼吸 + 不规则眨眼）
  - **裁行绕不开帧几何**：帧宽 = 图宽/8、帧高 = 帧宽 × 208/192（即 13:12）、行数 = 图高/帧高，三者都须整除成整数且行数 ≥ 9，否则**拒绝上传**（错误点名实际尺寸）。不做「按图高/9 猜」这类静默兜底——v2 图集是 8×11，除 9 会多裁 46px 到 running-right 行且毫无征兆。客户端渲染器用同一套判据（[src/shared/pet.ts](../../src/shared/pet.ts) 的 `deriveSheetGeometry`），所以这里拒掉的图集，宠物窗口本来也渲染不了，只是把失败提前到了上传时刻
  - 预览条是**整行 8 格**（含 idle 没画的第 7、8 格，那两格全透明）；客户端按规范表**只播前 6 帧**，字节数约为整图 1/9
  - **要求能解码 webp**：PetDex 默认扩展名就是 `.webp`，而 `javax.imageio` 原生读不了它；`.png` 走原生。输出格式不限（PNG 即可，不必额外引 webp 编码器）
- 落库字段：`name` = `manifest.name`；`event_count` / `audio_count` 统计包内事件集；`package_size` = 上传文件字节数；`package_url` 指向 OSS/CDN。**`main_agent` 列随 v2-only 切换一并删除**（v2 无此概念，不保留恒为 null 的字段）。
- **后缀（待同步）**：上传侧白名单同时收 `.zip` 与 `.tomochar`，无需配合；但**下载响应的 `Content-Disposition` 文件名仍是 `<角色名>.tomochar`**，网页端也按此后缀命名下载文件（见《角色库公开接口契约》）。服务端尚未跟着切到 `.zip`——**本条在服务端同步后删除**。客户端导入不看后缀，所以这不是阻塞项。
